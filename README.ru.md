# jobservice

[English](README.md) · Русский

Сборщик вакансий с [Jobs.cz](https://www.jobs.cz) и [StartupJobs.cz](https://www.startupjobs.cz) в SQLite.

## Установка

```sh
uv sync
cp .env.example .env   # ключевые слова, город, путь к БД
```

## Запуск

```sh
uv run jobservice collect                         # параметры из .env
uv run jobservice collect -k python -k django --city Praha --max-pages 2
uv run jobservice collect --source startupjobs --refresh
```

Повторный запуск обновляет существующие записи (ключ — `source` + `external_id`) и не
скачивает заново описания, которые уже есть в БД (`--refresh` — скачать заново).

## Фильтры

После каждого сбора применяются жёсткие фильтры. Отсеивается только при явных признаках,
при нехватке данных вакансия проходит. Отсеянные вакансии на странице не показываются, но
остаются в базе с причиной: так их не нужно заново оценивать при каждом сборе, а смена порогов
в `.env` применяется и к ним. Сводка причин: `uv run jobservice filter --stats`.

Вакансии делятся на два рынка: **Чехия** (Jobs.cz, StartupJobs) и **Украина (remote)**
(DOU.ua, через официальные RSS-ленты remote-вакансий по категориям
`JOBS_DOU_CATEGORIES` и опыту `JOBS_DOU_EXPERIENCE`; зарплаты в $ переводятся в € по `JOBS_EUR_USD`). На странице у каждого рынка своя вкладка
с числом новых вакансий; минимальная зарплата задаётся отдельно: `JOBS_MIN_SALARY_EUR` (Чехия,
1500 €) и `JOBS_MIN_SALARY_EUR_UA` (Украина, 1000 €). Отчёт показывает рынки отдельно.

- **Место:** `JOBS_CITY` или удалёнка (`JOBS_INCLUDE_REMOTE`).
- **Зарплата:** верх диапазона ниже `JOBS_MIN_SALARY_EUR` €/мес (CZK по курсу
  `JOBS_EUR_CZK`, почасовая × 160). Без зарплаты — проходит.
- **Уровень:** только senior / lead / head / principal… (medior проходит).
- **Языки:** чешский выше B1 или другой язык, кроме английского, русского, украинского.
- **Дубли:** одинаковые должность + компания; остаётся та, по которой уже есть
  решение, иначе с самым длинным описанием.

После изменения настроек: `uv run jobservice filter`.

## Оценка моделью

```sh
uv run jobservice score --limit 10      # пробный прогон
uv run jobservice score                 # все новые вакансии, прошедшие фильтры
uv run jobservice score --id 404        # одна вакансия
```

Каждая новая вакансия, прошедшая фильтры, вместе с профилем (`data/profile.md`: три базовых
резюме и предпочтения) уходит в Claude через Claude Code (`claude -p` без инструментов, ответ
по JSON-схеме). Модель возвращает балл 0–100 по каждому направлению (AI / QA / HR), порог входа
и до трёх пунктов «почему подходит» и «чего не хватает» (по-русски). Повторно оцениваются только
новые вакансии и те, у которых изменились текст, профиль или версия промпта (`--rescore` —
переоценить всё). Модель: `JOBS_SCORE_MODEL` в `.env` или `--model`, по умолчанию модель
Claude Code. После трёх ошибок подряд (например, исчерпан лимит) оценка останавливается.

## Просмотр и решения

```sh
uv run jobservice serve            # http://127.0.0.1:8000, Ctrl+C — остановить
```

Вкладки «Новые / Откликнуться / Позже / Пропущенные / Все», поиск по тексту, фильтр
по городу и сайту, сортировка по баллу (общему или по направлению) и по порогу входа.

При открытии вакансии модель пишет ответ на вопрос формы StartupJobs «Jak mohu vaši firmu
posunout vpřed?» (короткое сопроводительное письмо на языке вакансии, только факты из профиля;
в чешском тексте честно указан уровень чешского A2–B1). Текст сохраняется в базе, есть кнопки
«Копировать» и «Сгенерировать заново». Для отсеянных и пропущенных вакансий текст создаётся
только по кнопке. Вставляю и отправляю сам. На странице вакансии: **A** — откликаться, **L** — позже,
**S** — пропустить (с причиной). После решения открывается следующая вакансия.
Повторный сбор решения не сбрасывает. Сервер слушает только 127.0.0.1.

## Отчёт по расписанию

`uv run jobservice report` делает всё за один запуск: сбор → оценка моделью → фильтры, затем
уведомление macOS «Отчёт по вакансиям готов» с числом новых и подходящих вакансий и лучшей из
ждущих проверки (`--no-notify` — только в лог).

Если в `.env` заданы `JOBS_GMAIL_ADDRESS` и `JOBS_GMAIL_APP_PASSWORD` (пароль приложения
Google, нужна двухэтапная проверка: https://myaccount.google.com/apppasswords), отчёт приходит
письмом через Gmail SMTP со списком вакансий, ждущих проверки. Письмо уходит только на этот же
адрес. Если отправить не удалось, вместо письма показывается уведомление macOS.

Запуск раз в 2 дня в 12:00 (нечётные числа месяца) через launchd:
`~/Library/LaunchAgents/com.jobservice.report.plist`, лог: `~/Library/Logs/jobservice-report.log`.
Если Mac спал, пропущенный запуск выполнится при пробуждении.

```sh
launchctl kickstart gui/$(id -u)/com.jobservice.report      # запустить сейчас
launchctl bootout gui/$(id -u)/com.jobservice.report        # выключить
launchctl bootstrap gui/$(id -u) ~/Library/LaunchAgents/com.jobservice.report.plist  # включить
```

Чтобы запускать каждый день: в plist оставить в `StartCalendarInterval` один словарь
`Hour=12, Minute=0` без `Day`, затем выключить и включить задачу.

## Таблица `vacancies`

| поле | |
|---|---|
| `source`, `external_id` | `jobscz` / `startupjobs` и id вакансии на сайте |
| `title`, `company`, `city`, `url` | |
| `description_text`, `description_html` | описание текстом и в исходном HTML |
| `published_at` | ISO-дата публикации, если её удалось определить |
| `published_raw` | дата как её показал сайт (`10. listopadu`, `Končí zítra`…) |
| `first_seen_at`, `last_seen_at` | когда вакансию впервые / последний раз видел сборщик |
| `status`, `status_reason`, `status_at` | решение: `new` / `apply` / `later` / `skip`, причина пропуска, когда |

## Источники

- **StartupJobs** — JSON API, которым пользуется сам сайт (`back.startupjobs.cz`).
- **Jobs.cz** — HTML выдачи + страница вакансии. У вакансий на шаблонах работодателей
  (`*.jobs.cz/detail-pozice`) текст рендерится JavaScript'ом, поэтому для них сохраняется
  только краткое описание из `og:description`, а `description_html` пустой.
